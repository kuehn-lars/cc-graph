## 0.3.0 (2026-10-16)

Blind spots: files that import a change but were never opened, and files a shell command changed behind Claude's back, named while the turn is still running. What Claude does through the shell counts: reads with `cat`, `head` or `sed -n`, its own `sed -i` and heredoc edits with their line counts, deletions committed in the same command, merges, and changes in a subagent's worktree. Switchable in `/config` (F07, F14 `blindSpots`). Tested on Claude Code 2.1.296 and 2.1.301.

- Release: F07 Verified, ROADMAP v0.3 Done, F07's tickets deleted. The README names the `blindSpots` setting and marks v0.3 as the latest release.


- F07 shell reads: a file Claude prints with `cat`, `bat`, `nl`, `head`, `tail` or `sed -n` shows as `read` or `partial` with what it saw ("48 lines", "lines 1 to 5"), and, for a single-file read, its tokens and import candidates; a piped `cat` is not a read. A search and the reads of one call land in one write of `graph`. A `Bash` call the engine held read-only raises no `git` at all (F07-AC23..AC25, R18, R19).
- F07 own changes: after each `Write`, `Edit` or `NotebookEdit` the mod queues one refresh of its `git status` baseline (at most one waiting), so a file Claude wrote and a later command removed shows as `deleted` (F07-AC16, R13; AC3 and AC10 now have tests).
- F07 commits and merges: each `git status` takes `git rev-parse HEAD` with it, and when a command moved `HEAD` the mod runs `git diff --name-status -z --no-renames <old> <new>` (once, off the hook's path): a file the commit deleted shows as `deleted`, one a merge or checkout brought in as `created`, and an untracked file that was committed is not `deleted`, also in a repository's first commit (F07-AC17..AC19, AC27, R14, NFR-S5).
- F07 named changes: a file a command names (`sed -i … src/config.ts`, `printf >> src/db/redis.ts`, `rm -rf tickets/`), or a folder that holds it, is Claude's own edit, `edited` with "changed by `<command>`" and no counted lines, not a blind spot; a file it never named (`package.json` under `npm pkg set`) stays `blind`. An `edited` node without counted lines shows "edited", not "+0 −0" (F07-AC22, R17).
- F07 agent worktrees: a `Bash` call of a subagent that is not read-only runs `git status` (with `HEAD` and the diff) in `.claude/worktrees/agent-<id>`, or in the working tree when `git` cannot run there; each worktree keeps its own baseline, and what it finds lands on the working tree's node with "… in worktree agent-<id>". A subagent's `Write` or `Edit` in a worktree refreshes that worktree's baseline. A path under `.claude/worktrees/` is never a node (F07-AC20, AC21, R13, R15, R16).
- F07 shell changes tested in real sessions (`claude -p` and interactive, with skills, subagents and worktrees), at the owner's request. A file a command names and changes is Claude's own edit like an `Edit`: one with nothing of it in context shows `◐` "only what the command changed", not "search hits only" or "never read", and a created one shows "created" or "new", not "+0" (F07-AC30, AC31, R17). A path-like part of a word names a file too, so a `python3 -c` or `node -e` write is Claude's own (AC36). Such a change also runs the import search, so `sed -i` on `login.ts` flags its unopened importers (AC34, R2). A tracked change undone while `HEAD` stays (`git checkout --`, `git restore`, `git reset --hard`) is cleared, but not by `git stash` (AC35, R6).
- F07 shell reads: `head -50`, a bare `head` or `tail`, `sed -n '10,$p'` and `sed -n '5p'` say what they showed; a print piped into `head`, `tail` or `sed -n` (`cat -n a.ts | head -20`, `nl -ba a.ts | sed -n '1,40p'`) is a partial read; a `for f in …; do cat "$f"; done` loop reads each of its files (AC32, AC33, AC38, R19).
- F02, F07 where a command starts: Claude Code's `Bash` tool keeps a `cd` for the next call, so searches, reads and named changes resolve from `$.session.cwd()` read before the call (now on NFR-S1's allowlist), not from the session's directory (F02-AC20, F07-AC37, F02-R8).
- F02 a here-document's lines are text, not commands: a body line beginning with `grep` no longer cancels the real search, and `cat << EOF` reads no file named `EOF` (F02-AC21, R1). An error line that quotes its path (`"src/middleware": No such file or directory`) is no hit (F02-AC19, R2).
- F15 a subagent's shell change carries its id, so a file only a subagent touched stays subagent only; a ghost no agent touched no longer says "agent" in the list, and says "never opened" (F15-R1, R2).
- F07 the `blindSpots` setting (`/config`, "Look for blind spots with git"): off, the mod runs no `git` at all and the list has no Blind spots section; shell reads still show (F07-AC26, F14-AC4, R12).
- F07 outside edits: an `edited_text_file` attachment of the main loop marks the file `external`, "changed outside Claude; Claude was shown it", or keeps Claude's own change with that reason; it is never a blind spot. No session has raised one yet (F07-Q1), so the test's text is derived (F07-AC6, R7).
- F07 renames and history: a `mv` or `git mv` carries what Claude had of a file to its new path; a patch applied with `git apply` or `patch` is Claude's own edit; a deletion that a `HEAD` move brings back, and a change `git reset --hard` discards, is cleared (F07-AC39..AC42).
- RS-2 and RS-3 replay the reference session with `git` answered step by step; NFR-R3 has its own test.
- F07 from the owner's manual check: an `edited_text_file` that follows Claude's own `Bash` edit (Claude Code raises one after a command changes a file Claude printed) is Claude's edit, "changed by `…`", not an outside change; its recorded text answers F07-Q1 (AC43, R7). A file the person changed between turns shows as external, "changed outside Claude", or deleted outside Claude (AC44, R20). A file created and removed in one command, or any known file an `rm` removes, shows as deleted, `git` or not (AC45, R21). A second edit of an already changed file, and outside a repository any write to a known file (`>`, `>>`, `tee`, `sed -i`, `perl -i`), shows as edited (AC46, R22). A shell change in a worktree says "worktree" in its list row (F15-AC10).
- F09 the now line under the graph names the selected file (`⏺ selected`, picked with 1 to 9 in the list) or else the last one touched, and adds its reason and what Claude saw: `⏺ now  package.json  changed unseen  · changed by \`npm install left-pad\` · never read`. It is where the graph shows them until the detail card (F11) ships. A reason too long for the line shortens its command, so "in worktree agent-…" stays (F09-AC45, AC46, R18).
- F07 line counts for new files: a file a shell command creates (a heredoc, `printf >`, a generator) shows the lines it holds, "+3 new" in the graph and "created +3" in the list, counted by `git diff --numstat --no-index -- /dev/null <path>` off the hook's path (now allowed by NFR-S5); a later `>>` updates it. A tracked file a command changes that was clean before shows git's count, "+50 −200". A binary file still shows "new"; at most 20 files a call are counted (F07-AC47..AC50, R23).
- Spike S4 step 11: in an interactive session on 2.1.300 the `Bash` result's `bashEditDiff`, `gitOperation` and `staleReadFileStateHint` keys are present but always undefined.

## 0.2.0 (2026-10-14)

The graph: import edges in TypeScript and Python, switchable in `/config`, and the terminal graph that draws them, laid out by folder; files a shell command created, deleted or changed show too (F06, F09, F14 `importEdges`, F07 ticket 01). On other surfaces a ghost is a `⋯` row in the list, and its row names its importer. Tested on Claude Code 2.1.296.

- Release: F06 and F09 Verified, ROADMAP v0.2 Done. The README gets an animated header, badges, an annotated screenshot of the terminal graph and a timeline of every milestone.

- F09 layout: when a write adds or removes nodes or edges, one pass runs after the hook has returned and stores every node's position in `layout`. Files of a folder start around the folder's seed point, offset by a hash of their path; a pass is deterministic, takes at most 200 iterations and moves no node more than 2 units; positions of evicted nodes are dropped, and `/clear` empties `layout` (F09-AC1..AC3, AC12, R4, R13, F03-R7, NFR-P4).
- F09 queue: slow work is enqueued and drained by one coalesced `$.clock.after` callback, one job at a time, a failing job dropped (D5). At most one layout pass waits at a time; F07's `git` jobs use the same queue.
- F09 flow layout: importers settle at least 10 units above what they import and import edges pull to 14 units; a new node starts 8 units below its most recently touched placed importer (or above what it imports, or at its folder's seed point) and moves freely in its first pass, while nodes with an earlier position keep the 2-unit cap. Linked pairs skip the pairwise repulsion, so the spring alone sets an edge's length (F09-AC25, AC26, R4, R13).
- F09 boxes: each file is a rounded box on the terminal's own background holding its list glyph, its name and its change word, solid in context and dashed otherwise, with a size bar along its bottom side; a ghost is a tag without a box, and a character a `Raster` would refuse (wide, or outside the BMP) is drawn as `?`. Import edges are box-drawing lines at right angles that turn where they cross the fewest boxes and join the boxes' sides. The focus, the selected node or else the one Claude touched last, has its border and edges in Claude's orange. Colours are Claude Code's own theme keys: the lines around the graph follow the person's theme, and the raster paints the dark theme's values (F09-AC11, AC17, AC27..AC34, R23..R26, R29).
- F09 folders: each folder is a frame titled with its path (`src/auth/`, `./` at the root) around its files, so two `index.ts` can be told apart. Folders stack in layers, a folder that imports from another above it, with each layer's frames centred under their importers; inside a folder an importer's line sits above what it imports. Folders without imports either way fill free room at the top right. When the pane is short, the tallest folder's boxes become one-row tags first, and only then a folder is left out: one without a change before one with, the one touched longest ago first, never the focus's. Edges always run top down, enter where they cross the fewest boxes and titles, go round a folder in the way, and cross a frame at `┼` (F09-AC33, AC38..AC40, R26, R30).
- F09 colours: an edit reads `+2 −1` with the added lines green and the removed lines red, as a diff colours them; a deleted file's box, border and word are red and its name dimmed; a focused tag has its name in Claude's orange. The legend ends its first line with `━ size`, saying what the bar under a box is (tokens in context, against the largest file), and names `deleted` (F09-AC29, AC41..AC43, R24, R27..R29).
- F09 header, now line and legend: the keys row is led by `✻ CC Graph` and "what Claude knows"; the meter line reads `━━━━━━━━━━━━━━━━ 6% of 1M  ≈300 tokens · 3 files · 1 compacted · 1 changed unseen` ("window –" and no bar without a percent; a million or more tokens count as `1M`). Under the graph, `⏺ now  src/auth/login.ts  +2 −0  · imports 3` names the file Claude touched last, or says "Nothing read yet."; two legend lines name only the glyphs, `━ size`, the changes and the memory files on screen, ending in "…" when wider than the pane. Below 8 rows for the graph the list is drawn with "Graph needs a taller pane". The list says what the graph draws: a file's row ends with `imports n`, a ghost's says `imported by login.ts` and `+n` for further importers (F09-AC7, AC10, AC21, AC22, AC35, AC37, R2, R10, R11, R18, R21, R28, NFR-A3).
- F09 pulse: when Claude touches a file while the graph is shown, its border (a tag's name) flashes white, then Claude's shimmer colour, then orange, and returns to the plain frame, by four `$.ui.blit` calls at 0, 120, 240 and 400 ms that add no render pass. It waits for the layout pass and its redraw; a render in between ends it, a newer pulse stops an older one, and a denied blit is ignored (F09-AC36, R27).
- F07 shell changes (pulled into v0.2): after each `Bash` call the mod compares `git status` with its baseline, off the hook's path, and marks what the command did: `created` (untracked, added, renamed to), `deleted` (`D`, renamed from, or an untracked file gone) or `changed unseen`, each with "created by", "deleted by" or "changed by" and the command. A file Claude changed with `Write` or `Edit` is never blamed on a command. Outside a repository the footer says "Shell changes need git" (F07-AC2, AC12..AC15, R1, R5, R6, R8).
- F07 importers Claude never opened: after an `Edit` or `Write` the mod queues one `git grep` per path and turn (off the hook's path), confirms each hit with F06's resolver, and adds importers with no node as `ghost`s with a `blind` edge to the changed file; opening the ghost clears the edge. The list view gains a Blind spots section: the newest five, "imports login.ts, never opened" or a command's "changed by …", else "No blind spots." (F07-AC1, AC7..AC9, AC11, R2..R4, R10). The graph draws a blind edge dashed (`╌ ╎`) in the error colour (F09-R26, AC44).
- F07 when git fails: a `git` job (status, refresh, import search) that fails or runs past its 5 second timeout is dropped, its reason goes to the debug log (`$.ui.log` with `to: 'debug'`, now on NFR-S1's allowlist), and the footer says "Blind-spot search timed out" once per conversation; the `Edit` or `Bash` result Claude received is unaffected (F07-AC4, AC5, R9).
- F07 importers, two more forms: a changed `index` or `__init__` file is searched by its folder's name (`from '../auth'` finds `src/auth/index.ts`), and the last line of a multi-line import, `} from '../auth/login'`, is confirmed (F07-AC28, AC29, R2).
- F02 an `ls` after a search in the same command no longer adds its folder headers (`src/auth:`) as search nodes; only a line that is a path and its colon is skipped, so a hit whose text ends in `:` stays a hit (F02-AC18, R2).
- Faster terminal frames: the raster is one typed array encoded as is, and edge routing sums its costs without building paths (NFR-P3).

- F06 import edges: a successful text `Read`, `Write` or `Edit` links the file to the files it imports, parsed from `file.content`, `content` and `newString`. The node, its edges and its ghosts land in one write of `graph`, under the same eviction cap (F06-AC1, AC8, R1, I5, I9). The mod reads no file to find them (F06-AC4, R8).
- F06 import edges: an imported file with no node becomes a `ghost`, held by nobody (`mainLoop: false`, no agents). An existing node keeps its state (F06-R7).
- F06 import edges: one edge per pair of files, none from a file to itself, and none removed; a second read of `login.ts` adds nothing (F06-AC10, R10).
- F06 TypeScript, with JavaScript (`.ts`, `.tsx`, `.mts`, `.cts`, `.js`, `.jsx`, `.mjs`, `.cjs`): `import … from`, `import 'x'`, `export … from`, `require('x')` and `import('x')`. Comments and strings that look like imports are skipped. Only relative specifiers link: packages, `node:` built-ins and aliases such as `@/lib/x` add nothing (F06-AC2, AC9, R2, R5).
- F06 TypeScript resolution: the path as written when it has a known extension, then each extension of the importer's own family, then the other family, then `/index`. A TypeScript file's `./util.js` tries `util.ts`, then `util.tsx`, before the path as written, and `.jsx`, `.mjs` and `.cjs` try `.tsx`, `.mts` and `.cts`. `.`, `..` and `x/` name a folder's index. An import whose extension belongs to no language (`./styles.css`, `./user.service`) links only to a node that already exists, so it makes no ghost such as `styles.css.ts`. A target outside the working directory keeps its absolute path (I4), so imports from a sibling package link too (F06-AC7, R3).
- F06 Python (`.py`): `from .x import y`, `from . import x`, `from ..x import y`, `import a.b` and `from a.b import c`. Each extra dot goes one package up, and `x.py` is tried before `x/__init__.py`. An absolute module links only to a node that already exists (F06-AC3, R2, R4).
- F06 picking a target: a candidate that is already a node, and not a ghost, wins, and the edge is not `guessed`. Otherwise the first candidate wins, the edge is `guessed`, and its target becomes a ghost. A ghost does not confirm anything, so a second importer of a guessed file still guesses (F06-AC6, R6; F06-Q3 open on clearing `guessed` later).
- F06 limits: text over 200,000 characters adds nothing, whichever of the three tools it came from, and so does a file whose extension belongs to no language, such as an import shown in `docs/usage.md` (F06-AC5, AC11, R9, R11). AC5's 300,000-character `Read` and the R9 and self-import cases are derived from recorded results, because a `Read` over 256 KB errors.
- F06 setting: `importEdges` ("Show file imports", on by default, F14-R1) in `/config`. When it is off, a `Read`, `Edit` or `Write` parses no imports, so a read of `login.ts` adds `login.ts` alone, with no edge and no ghost (F06-AC12, R12). Edges already in the graph stay until `/clear` (F06-Q2).
- F06 recording: `fixtures/sessions/imports.ts` comes from a real `claude -p` run that reads `src/auth/password.js`, `src/auth/login.ts`, `src/a.ts`, `app/models.py`, `app/views.py` and `docs/usage.md`. It is written by `scripts/record-imports-session.mjs` with the `imports-probe` mod, and `fixtures/sessions/README.md` explains how to record it again.
- Specs: F06 Approved. Each language is one entry (TypeScript with JavaScript, and Python), and R6 now says a ghost is a guess, not a confirmation. F14 gains the `importEdges` row, and ROADMAP v0.2 gains F14 (`importEdges`) and its exit gate.
