# Changelog

Versions follow semver. Each release names the Claude Code versions it was tested on.

## Unreleased

F06 import edges are in the graph state, and the terminal graph (F09) now draws them. On other surfaces a ghost is a `⋯` row in the list, and its row names its importer. F06's manual check waits for F09's (ticket 07).

- F09 layout: when a write adds or removes nodes or edges, one pass runs after the hook has returned and stores every node's position in `layout`. Files of a folder start around the folder's seed point, offset by a hash of their path; a pass is deterministic, takes at most 200 iterations and moves no node more than 2 units; positions of evicted nodes are dropped, and `/clear` empties `layout` (F09-AC1..AC3, AC12, R3, R4, F03-R7, NFR-P4).
- F09 queue: slow work is enqueued and drained by one coalesced `$.clock.after` callback, one job at a time, a failing job dropped (D5). At most one layout pass waits at a time; F07's `git` jobs will use the same queue.
- F09 graph: nodes are drawn at their stored position (a node with none, at its folder's seed point) and each import edge as a line of half-block pixels between node cells, the glyphs on top. A cell with only its bottom pixel lit is `▄` (F09-R1 amended: `▀` would paint the unlit top in the terminal's foreground) (F09-R1, R5, R9, NFR-P3).
- F09 rings, memory and legend: a changed node's cell takes its ring as background (amber edited, green created, grey external, red blind); memory files are `■` cells along the bottom-left in path order, and nodes keep off them. A legend line under the graph names the glyphs, the `■` and the rings on screen and no other, cut and closed by `…` when wider than the pane; it takes a row from the raster. The list says what the graph draws: a file's row ends with `imports n`, a ghost's says `imported by login.ts` and `+n` for further importers (F09-AC8, AC10, R1, R5, R8, R10, NFR-A3).
- F09 labels: the selected node, changed nodes and the 5 largest by tokens show their file name to the right of their cell. A label that would cover a node or memory cell, another label, or run off the raster is dropped, so no glyph is erased (F09-R6 amended with AC6); a character a `Raster` would refuse (wide, or outside the BMP) is drawn as `?` (F09-AC6, AC11, R6, NFR-A3).

- F06 import edges: a successful text `Read`, `Write` or `Edit` links the file to the files it imports, parsed from `file.content`, `content` and `newString`. The node, its edges and its ghosts land in one write of `graph`, under the same eviction cap (F06-AC1, AC8, R1, I5, I9). The mod reads no file to find them (F06-AC4, R8).
- F06 import edges: an imported file with no node becomes a `ghost`, held by nobody (`mainLoop: false`, no agents). An existing node keeps its state (F06-R7).
- F06 import edges: one edge per pair of files, none from a file to itself, and none removed; a second read of `login.ts` adds nothing (F06-AC10, R10).
- F06 TypeScript, with JavaScript (`.ts`, `.tsx`, `.mts`, `.cts`, `.js`, `.jsx`, `.mjs`, `.cjs`): `import … from`, `import 'x'`, `export … from`, `require('x')` and `import('x')`. Comments and strings that look like imports are skipped. Only relative specifiers link: packages, `node:` built-ins and aliases such as `@/lib/x` add nothing (F06-AC2, AC9, R2, R5).
- F06 TypeScript resolution: the path as written when it has a known extension, then each extension of the importer's own family, then the other family, then `/index`. A TypeScript file's `./util.js` tries `util.ts`, then `util.tsx`, before the path as written, and `.jsx`, `.mjs` and `.cjs` try `.tsx`, `.mts` and `.cts`. `.`, `..` and `x/` name a folder's index. An import whose extension belongs to no language (`./styles.css`, `./user.service`) links only to a node that already exists, so it makes no ghost such as `styles.css.ts`. A target outside the working directory keeps its absolute path (I4), so imports from a sibling package link too (F06-AC7, R3).
- F06 Python (`.py`): `from .x import y`, `from . import x`, `from ..x import y`, `import a.b` and `from a.b import c`. Each extra dot goes one package up, and `x.py` is tried before `x/__init__.py`. An absolute module links only to a node that already exists (F06-AC3, R2, R4).
- F06 picking a target: a candidate that is already a node, and not a ghost, wins, and the edge is not `guessed`. Otherwise the first candidate wins, the edge is `guessed`, and its target becomes a ghost. A ghost does not confirm anything, so a second importer of a guessed file still guesses (F06-AC6, R6; F06-Q3 open on clearing `guessed` later).
- F06 limits: text over 200,000 characters adds nothing, whichever of the three tools it came from, and so does a file whose extension belongs to no language, such as an import shown in `docs/usage.md` (F06-AC5, AC11, R9, R11). AC5's 300,000-character `Read` and the R9 and self-import cases are derived from recorded results, because a `Read` over 256 KB errors.
- F06 setting: `importEdges` ("Show file imports", on by default, F14-R1) in `/config`. When it is off, a `Read`, `Edit` or `Write` parses no imports, so a read of `login.ts` adds `login.ts` alone, with no edge and no ghost (F06-AC12, R12). Edges already in the graph stay until `/clear` (F06-Q2).
- F06 recording: `fixtures/sessions/imports.ts` comes from a real `claude -p` run that reads `src/auth/password.js`, `src/auth/login.ts`, `src/a.ts`, `app/models.py`, `app/views.py` and `docs/usage.md`. It is written by `scripts/record-imports-session.mjs` with the `imports-probe` mod, and `fixtures/sessions/README.md` explains how to record it again.
- Specs: F06 Approved. Each language is one entry (TypeScript with JavaScript, and Python), and R6 now says a ghost is a guess, not a confirmation. F14 gains the `importEdges` row, and ROADMAP v0.2 gains F14 (`importEdges`) and its exit gate.

## 0.1.0 (2026-10-13)

What Claude knows: a list view of every file Claude read, searched or changed, what compaction took, how full the window is, and which memory files are in force (F01, F02, F03, F04, F08, F14 `maxNodes`, F15). Tested on Claude Code 2.1.296.

- Plugin skeleton: `plugin.json`, `marketplace.json`, an empty hooks module, the `$.state` contract (02 Data model) and the Claude Code 2.1.296 types.
- `fixtures/sample-app` (04 Reference session) and real `rg`, `grep` and `git` output in `fixtures/output/`, with `capture.sh` to record it again.
- `scripts/trace.mjs`, `scripts/check-calls.mjs` and CI on Claude Code 2.1.296 and `latest`.
- Spike S0 (ARCH-Q1): off-path `$.clock.after` work may run `git` and write state after its hook returned, and the write redraws the pane.
- Spike S1 (F03-Q1, F07-Q1): `file` attachments after a compaction name the absolute path on their first line; no `edited_text_file` was seen in 2.1.296.
- F01 file tracking: a successful text `Read` becomes a `read` or `partial` node with `seen`, `tokens` and `readId`; paths are relative to the working directory (F01-AC1..AC3, AC7, AC10).
- F01 file tracking: image, PDF, PDF page range and notebook reads become `read` nodes with `tokens: null` and a `seen` naming the kind (F01-AC11, R2). `file_unchanged` is handled too (below).
- F01 file tracking: a successful `Edit` or `NotebookEdit` marks the node `edited` with `+added −removed` counted from the written patch, and keeps its state (F01-AC4, AC14, R4, R5).
- F01 file tracking: a `Write` marks the node `created` or `edited`, and `created` survives later edits and writes; staged writes change nothing (F01-AC5, AC6, AC13, R6).
- F01 file tracking: `@`-mentioned files become `read`, `partial` (ranged) or `ghost` (PDF not attached) nodes; denied mentions change nothing (F01-AC9, AC15, AC16, R7).
- F01 file tracking: the hooks return the tool result unchanged across the recorded reference session (F01-AC8, R10).
- F01 file tracking: `file_unchanged` leaves an existing node as it is (a compacted file stays compacted) and makes a missing one `read`, "unchanged since an earlier read" (F01-R3, AC12, AC23). Its test result is derived from the type, not recorded: no 2.1.296 session returned one.
- F01 file tracking: a mention changes only a missing or `ghost` node, and only touches `lastTurn` and `touched` on any other (F01-R7, AC18..AC22); a partial read keeps the whole read's `readId` (F01-AC17). Recordings now set the numbers of AC4, AC5 and AC14, and AC8 means deep equality.
- Specs follow the reference recording: `fixtures/sessions/reference.ts`, 121 lines for `routes/index.ts`, compaction 22,694 to 4,959 tokens, `log_decision` answers a JSON string (F12-R4), `npm test` exits 1 (04 Reference session). Tests may use results marked derived (CLAUDE.md).
- F08 pane: `/graph` is registered at `session.start` and opens pane `cc-graph` (focused, closes on Esc, 64 columns); one `ui.render` hook matching only that pane draws the Files section, "Nothing read yet." on an empty graph; a pane that waits shows its reason in a toast (F08-AC1, AC7, R1..R3, R12, NFR-R4).
- F08 views: `/graph list` and `/graph graph`, and the `l` and `g` buttons, set `view` in `$.state`; every surface draws the list until F09 or F10 ships (F08-AC4, AC5, R2, R9..R11, NFR-C2). With no surface the argument still sets `view` and `/graph` still answers in text (F08-R2).
- F08 list view: every file in the graph is one row in Files, newest first: state glyph, path, change badge and "≈tokens · seen" ("≈?" when unknown) (F08-AC2, R5, NFR-A1). AC2 replays steps 1 to 6 of the reference session (seeded until F02 shipped).
- F08 text summary: with no surface, `/graph` opens no pane and answers the count of files per state, then per change, zero counts left out (F08-AC8, R4, NFR-C3). AC8 replays steps 1 to 3 (seeded until F02 shipped).
- F08 list view: rows fit `bodyColumns`, counted in terminal columns: a long path is cut from its start and led by "…" so the file name stays; if the name alone does not fit with the badge and size, those are dropped from the end (F08-AC3, AC10, R6).
- F08 list view: every file row is a plain `Button` keyed by its path; a press (click, Tab and Enter, or `1` to `9` on the first nine rows) sets `selected` and writes nothing else. Hotkey rows give up 3 columns to the "1: " label (F08-AC6, AC9, R8, NFR-A2).
- F08 selected row: the row whose path is `selected` begins with "▸ ", the others with two spaces, so a press is visible before the card of F11 (F08-R13, AC11).
- F02 search tracking: a successful `Bash` search (`rg`, `grep`, `egrep`, `fgrep`, `git grep`) turns each file in its hits into a `search` node with `hits`, `tokens`, `readId` and "N search hits, never opened"; a `read` or `partial` node keeps its state and only counts hits; a `compacted` node restarts and says "since compaction". One call adds one copy, so a repeated search adds its hits and tokens again (F02-AC1, AC2, AC4, AC6, AC7, AC12..AC14, R4..R7).
- F02 search tracking: searches inside pipelines and chains count, a search reading standard input does not, and a command with two file-reading searches adds nothing (F02-AC5, AC11, AC17, R1, R3, R10). Flag values (`-t ts`) and redirections (`2>&1`) are not operands (F02-R2).
- F02 search tracking: `-l`, a single file operand, and the no-hit modes (`-c`, `--count-matches`, `--files`, `--json`, `-q`, `-L` for grep and git grep) are read as the spec says; `rg -L` is `--follow` and its hits count (F02-AC3, AC9, AC10, AC16, R2, R3).
- F02 search tracking: relative hits resolve under a literal `cd <dir> &&`; an unknown directory drops the hits (F02-AC8, R8).
- F02 search tracking: a persisted output is parsed from the preview Claude read (`text`), less its wrapper lines. Recorded in `fixtures/tool-results/bash-persisted.ts`: `stdout` held the first 30,000 characters, so it would overcount about 15 times (F02-AC15, R9).
- F02 reference session: RS-1 is reached by replay; the F08 tests no longer seed (RS-1, F08-AC2, AC8).
- F03 compaction: a main-loop `/compact` or automatic compaction turns every `read`, `partial` and `search` node `compacted` unless its `readId` is among the kept messages' tool uses; changes stay, and one `CompactMark` records the turn, trigger, before and after tokens and `kept`. A subagent's compaction, a `{ skip }` and a `precompute` change nothing (F03-AC1..AC3, AC6, AC7, AC9, R1, R2, R8).
- F03 re-attachment: a `file` attachment naming a `compacted` node makes it `read` again, "re-attached after compaction", sized from the text; memory files and other nodes are left alone (F03-AC11, R3).
- F03 meter: `session.measure` stores `fill`; the list view and the `/graph` text start with "≈12.4k in 7 files (+2 unknown) · window 41% of 200k", "window –" until a fill is reported (F03-AC5, AC12, AC13, R4..R6, R9).
- F03 reset: `classic.SessionStart` with `clear`, `resume` or `fork` empties every key but `view`; `compact` and `startup` change nothing (F03-AC8, AC10, R7). The reference session reaches RS-4.
- F15 subagents: a `tool.call` with `agentId` applies F01's and F02's rules and adds the id to the node's `agents` once; a node only an agent touched is `mainLoop: false`, stays out of the meter and through a main-loop compaction, and its list row says "agent" (F15-AC1, AC3, AC5, R1..R3, R5).
- F15 main loop owns the state: once `mainLoop` is true a subagent's call only adds its id and stamps `touched`; the main loop's first touch of a subagent-only node sizes it as if new and keeps its change, line counts, agents and `firstTurn` (F15-AC2, AC7, AC8, R6, R8).
- F15 agent names: the first `tool.call` of an agent id asks `$.agent.list()` once and stores `{ id, type, description }` under `agents` (an unlisted id is type "agent", described by its first 8 characters); `/clear`, `/resume` and `/branch` empty `agents` (F15-AC4, AC6, R4).
- F15 worktrees: a path under `.claude/worktrees/‹name›/` in the working directory names the repository's file (I4); an agent's `Edit`, `Write` or `NotebookEdit` there sets `reason` "in worktree ‹name›", a later change elsewhere sets it back to `null`, and the list row says "worktree" (F15-AC9, AC10, R9).
- F15 attribution gaps closed: a `file_unchanged` result and a `prompt.mention` with `agentId` attribute the node like any call (a new agent id, or the main loop on a subagent-only node, touches it; otherwise it stays untouched), and a worktree change never overwrites a change made in the working tree (F15-AC11..AC13, R1, R9).
- F04 memory layer: `session.start` and a `session.measure` that reports `context` read the memory files from `$.session.usage({ breakdown: 'summary' })` (never `full`) and replace the notes it lists, keeping their reason and any nested, path-rule or import note it does not list (F04-R1, R2, AC1..AC3, AC6, AC8).
- F04 memory layer: `classic.InstructionsLoaded` notes a loaded memory file at once with its type and reason, and a main-loop `nested_memory` attachment sizes the nested note locally (F04-R3, R6, AC4, AC5, AC7). A nested `CLAUDE.md` that Claude reads with `Read` loads no memory note (F04-Q2).
- F14 recordings: `fixtures/sessions/wide.ts` (30 files, 26 read over two turns, one search, three edits) and `many-changes.ts` (24 files written), with `wide-probe/` and `scripts/record-wide-session.mjs`, for the cap tests (F14-AC1, AC8).
- F14 over-cap note: when changed files alone exceed `maxNodes`, the graph keeps them all and the list view footer says "N files over the cap of M"; the note goes once the graph is back under the cap. The footer draws the newest five notes, one line each, and nothing without a note (F14-AC8, F08-R5, I5).
- F14 settings: `maxNodes` ("Most files in the graph", default 60, 20 to 200) is declared in `userConfig` and read once by `register`; I5 evicts oldest unchanged files inside the write that exceeds it and never a changed file. A changed value applies at the next write. The other settings ship with their features (F14-AC1, AC3, AC5, AC8, R1..R3, R6).
- `trace.mjs`: a criterion marked `(from vX.Y)` after its ID is required only once `plugin.json` reaches that milestone, so a spec whose fields ship over several milestones can be Implemented (F14-AC2, AC4, AC6, AC7).
- v0.1 NFR tests: a `tool.call` benchmark (NFR-P1, best of three runs of 200 calls), the state size after a 500-call fixture (NFR-P5), fault injection in non-gating hooks (NFR-R2), ten parallel reads (NFR-R5), a second `session.start` (NFR-R6), every surface (NFR-C2) and paths as macOS, Linux and Windows spell them (NFR-C4).
